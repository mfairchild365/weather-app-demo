# Implementation Plan: Platform Foundation

**Branch**: `001-platform-foundation-npm` | **Date**: 2026-07-27 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-platform-foundation-npm/spec.md`

## Summary

Stand up the npm workspaces monorepo, a normalized Postgres schema managed with Drizzle ORM and
checked-in migrations, three least-privilege database roles, a Docker Compose stack that runs
migrations before any dependent service, and a base GitHub Actions CI pipeline (lint/typecheck/
unit/migration-smoke). No application behavior (API routes, ingestion, UI) ships in this feature —
those are `002-weather-ingestion` and `003-forecast-browser`.

## Technical Context

**Language/Version**: TypeScript 5.x on Node.js 22 LTS

**Primary Dependencies**: Drizzle ORM + drizzle-kit, `pg`, ESLint (flat config) + `typescript-eslint`,
Prettier, Vitest

**Storage**: PostgreSQL 16

**Testing**: Vitest (unit); migration-smoke check via a `postgres:16` service container in CI

**Target Platform**: Linux containers (Docker), GitHub Actions runners

**Project Type**: Web application monorepo (npm workspaces)

**Performance Goals**: N/A for this feature (no request-serving code yet)

**Constraints**: No secrets required to run base CI; every schema change is a checked-in migration;
zero source files over 600 lines

**Scale/Scope**: One workspace root + `packages/db` (this feature); `packages/api`, `packages/
ingest`, `packages/ui`, `packages/web` are scaffolded as empty workspace stubs so `npm install`
and root scripts already fan out to them, with real content added in later features
